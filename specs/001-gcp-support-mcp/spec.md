## User Scenarios & Testing *(mandatory)*

Google Cloud를 운영하는 엔지니어와 지원 담당자가, AI 어시스턴트와 대화하는 자리를 떠나지 않고 Google Cloud 지원 케이스를 조회하고 처리할 수 있도록 하는 MCP 서버다. 사용자는 콘솔을 새로 열거나 별도의 CLI를 익히지 않고, 평소 쓰던 어시스턴트에게 "지금 열려 있는 케이스 알려줘", "이 케이스에 로그 요약을 코멘트로 달아줘" 같은 요청을 그대로 한다.

### User Story 1 - 지원 케이스 조회 및 상황 파악 (Priority: P1)

운영 엔지니어가 담당 프로젝트 또는 조직에 걸려 있는 지원 케이스의 현재 상태를 확인한다. 열려 있는 케이스 목록을 보고, 특정 케이스의 상세 내용(제목, 우선순위, 상태, 담당 지원팀 정보)을 확인하며, 지금까지 오간 코멘트 대화 내역과 첨부된 파일 목록을 읽는다. 조건을 걸어 케이스를 검색할 수도 있다.

**Why this priority**: 지원 업무 시간의 대부분은 "지금 무슨 일이 어디까지 진행됐는가"를 파악하는 데 쓰인다. 이 스토리만 구현해도 콘솔을 열지 않고 상황 파악이 끝나므로 그 자체로 독립적인 가치가 있다. 또한 모든 쓰기 동작은 대상 케이스를 먼저 특정해야 하므로, 이후 스토리의 전제가 된다.

**Independent Test**: 실제 지원 케이스가 존재하는 프로젝트를 대상으로, 어시스턴트에게 케이스 목록 조회 → 특정 케이스 상세 조회 → 해당 케이스의 코멘트 목록 조회를 순서대로 요청했을 때, 콘솔에서 보이는 내용과 동일한 정보가 반환되는지로 검증한다. 쓰기 기능이 전혀 없어도 완결적으로 동작한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 접근 권한을 가진 프로젝트에 열린 케이스가 여러 건 있을 때, **When** 사용자가 해당 프로젝트의 케이스 목록을 요청하면, **Then** 각 케이스의 식별자, 제목, 상태, 우선순위, 생성 시각이 함께 반환된다.
2. **Given** 케이스 식별자를 알고 있을 때, **When** 사용자가 그 케이스의 상세 정보를 요청하면, **Then** 케이스 본문 설명, 분류, 상태, 우선순위, 관련 연락처 정보가 반환된다.
3. **Given** 지원팀과 여러 차례 대화가 오간 케이스가 있을 때, **When** 사용자가 그 케이스의 대화 내역을 요청하면, **Then** 코멘트가 시간 순서와 작성자 구분(고객 측/지원팀 측)이 드러나는 형태로 반환된다.
4. **Given** 조회 결과가 한 번에 반환하기에 많을 때, **When** 사용자가 목록을 요청하면, **Then** 일부 결과와 함께 "더 남아 있음"이 사용자에게 드러나고, 이어서 나머지를 요청할 수 있다.
5. **Given** 사용자가 접근 권한이 없는 프로젝트를 지정했을 때, **When** 조회를 요청하면, **Then** 권한 부족이라는 사실과 어떤 권한/지원 플랜이 필요한지가 사람이 읽을 수 있는 문장으로 반환된다.

### User Story 2 - 케이스 생성 및 대화 참여 (Priority: P2)

엔지니어가 장애 상황을 정리한 내용을 그대로 새 지원 케이스로 제출한다. 케이스를 만들기 전에 어떤 제품/문제 분류를 골라야 하는지 검색해 확인하고, 적절한 분류·제목·설명·우선순위를 지정해 케이스를 연다. 이미 열려 있는 케이스에는 추가 정보나 로그 요약을 코멘트로 남긴다.

**Why this priority**: 조회가 가능해진 다음으로 가치가 큰 동작이다. 장애 대응 중 맥락을 다시 옮겨 적는 비용이 사라진다. 다만 외부(Google 지원팀)에 실제로 전달되는 동작이므로 조회보다 뒤에 온다.

**Independent Test**: 테스트 대상 프로젝트에서 분류 검색 → 케이스 생성 → 생성된 케이스에 코멘트 추가를 요청하고, 생성된 케이스가 콘솔에서 동일한 내용으로 보이는지 확인한다. P3의 수명주기 기능이 없어도 완결된다.

**Acceptance Scenarios**:

1. **Given** 사용자가 어떤 분류를 써야 할지 모르는 상태에서, **When** 제품명이나 증상 키워드로 분류를 검색하면, **Then** 케이스 생성에 사용할 수 있는 유효한 분류 후보 목록이 반환된다.
2. **Given** 유효한 분류와 제목·설명·우선순위가 준비되었을 때, **When** 사용자가 케이스 생성을 요청하면, **Then** 실행 전에 제출될 내용 전체가 사용자에게 제시되고 명시적 확인을 받은 뒤에만 케이스가 생성되며, 생성된 케이스 식별자가 반환된다.
3. **Given** 열려 있는 케이스가 있을 때, **When** 사용자가 코멘트 추가를 요청하면, **Then** 작성될 코멘트 본문이 먼저 제시되고 확인을 받은 뒤에만 등록된다.
4. **Given** 필수 항목(분류, 제목, 설명 등)이 빠졌거나 분류가 유효하지 않을 때, **When** 생성을 시도하면, **Then** 케이스는 생성되지 않고 어떤 항목이 왜 부족한지가 반환된다.

### User Story 3 - 케이스 수명주기 관리 및 첨부 파일 (Priority: P3)

담당자가 케이스의 우선순위나 제목 등을 수정하고, 해결된 케이스를 종료하며, 대응이 지연되는 케이스를 에스컬레이션한다. 지원팀이 올린 첨부 파일을 내려받아 내용을 확인하고, 로그 파일 등을 케이스에 첨부한다.

**Why this priority**: 사용 빈도가 상대적으로 낮고, 특히 에스컬레이션은 Google 지원 조직에 실제 영향이 큰 동작이라 가장 신중하게 다뤄야 한다. P1·P2 없이 단독으로는 의미가 적으므로 마지막에 온다.

**Independent Test**: 테스트 케이스를 대상으로 우선순위 변경 → 첨부 파일 목록 조회 및 다운로드 → 케이스 종료를 요청하고, 각 동작이 확인 절차를 거쳐 반영되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 열려 있는 케이스가 있을 때, **When** 사용자가 우선순위 상향을 요청하면, **Then** 변경 전/후 값이 제시되고 확인을 받은 뒤에만 반영된다.
2. **Given** 해결된 케이스가 있을 때, **When** 사용자가 종료를 요청하면, **Then** 되돌릴 수 없는 동작임이 안내되고 확인을 받은 뒤에만 종료된다.
3. **Given** 에스컬레이션이 활성화된 상태에서 대응이 지연된 케이스가 있을 때, **When** 사용자가 에스컬레이션을 요청하면, **Then** 이 동작이 Google 지원 조직에 실제 전달되는 조치임이 명확히 안내되고, 사유 입력과 명시적 확인을 모두 받은 뒤에만 실행된다.
4. **Given** 첨부 파일이 있는 케이스에서, **When** 사용자가 특정 첨부 파일 다운로드를 요청하면, **Then** 파일이 사용자가 접근 가능한 위치에 저장되고 그 위치가 반환된다.
5. **Given** 관리자가 쓰기 동작을 비활성화한 상태에서, **When** 사용자가 종료나 에스컬레이션을 요청하면, **Then** 해당 기능이 꺼져 있다는 사실과 활성화 방법이 안내되고 아무 변경도 일어나지 않는다.

---

### Edge Cases

- 대상 프로젝트/조직이 유료 지원 플랜에 가입되어 있지 않아 지원 케이스 기능 자체를 쓸 수 없는 경우, 권한 오류와 구분되는 안내가 필요하다.
- 자격 증명이 없거나 만료된 상태에서 요청이 들어온 경우, 인증을 어떻게 설정해야 하는지 안내한다.
- 케이스 식별자를 잘못 지정했거나 이미 종료된 케이스에 종료·에스컬레이션을 시도한 경우.
- 조회 결과가 수백 건에 달해 한 번에 전달하면 대화 맥락을 압도하는 경우.
- 첨부 파일이 매우 크거나 어시스턴트가 직접 해석할 수 없는 형식인 경우.
- Google 측 요청 한도(rate limit)나 일시적 장애로 요청이 거절된 경우, 재시도 가능 여부를 구분해 안내한다.
- 케이스 본문·코멘트에 고객 데이터나 자격 증명이 포함될 수 있으므로, 반환 내용이 그대로 로그에 남지 않아야 한다.
- 확인 절차 도중 사용자가 취소한 경우, 어떤 변경도 남지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**조회 (Read)**

- **FR-001**: 시스템은 지정된 프로젝트 또는 조직에 속한 지원 케이스 목록을 조회할 수 있어야 한다. (조건 없는 조회이므로 FR-002의 검색과 **하나의 인터페이스로 제공될 수 있다** — 별도 수단을 요구하지 않는다.)
- **FR-002**: 시스템은 상태(열림/닫힘), 우선순위, 생성 시각 등의 조건으로 지원 케이스를 검색할 수 있어야 한다.
- **FR-003**: 시스템은 특정 케이스의 상세 정보(제목, 설명, 분류, 상태, 우선순위, 생성/갱신 시각, 에스컬레이션 여부)를 조회할 수 있어야 한다.
- **FR-004**: 시스템은 특정 케이스의 코멘트 목록과 개별 코멘트를, 작성자 구분과 작성 시각을 포함해 조회할 수 있어야 한다.
- **FR-005**: 시스템은 특정 케이스의 첨부 파일 목록과 개별 첨부 파일의 메타데이터(파일명, 크기, 등록 시각)를 조회할 수 있어야 한다.
- **FR-006**: 시스템은 케이스 생성 시 사용할 수 있는 유효한 문제 분류를 키워드로 검색할 수 있어야 한다.
- **FR-007**: 시스템은 결과가 많은 목록형 조회에 대해, 결과를 나누어 반환하고 다음 묶음을 이어서 요청할 수 있는 수단을 제공해야 한다.

**쓰기 (Write)**

- **FR-008**: 사용자는 분류, 제목, 설명, 우선순위를 지정해 새 지원 케이스를 생성할 수 있어야 한다.
- **FR-009**: 시스템은 케이스 생성 시 분류가 FR-006으로 확인 가능한 유효한 값인지 확인해야 하며, 유효하지 않으면 생성을 진행하지 않고 사유를 반환해야 한다.
- **FR-010**: 사용자는 기존 케이스에 코멘트를 추가할 수 있어야 한다.
- **FR-011**: 사용자는 기존 케이스의 수정 가능한 속성(제목, 설명, 우선순위 등)을 변경할 수 있어야 한다.
- **FR-012**: 사용자는 기존 케이스를 종료할 수 있어야 한다.
- **FR-013**: 사용자는 기존 케이스를 사유와 함께 에스컬레이션할 수 있어야 한다.
- **FR-014**: 사용자는 케이스의 첨부 파일을 내려받을 수 있어야 하며, 파일에 접근 가능한 위치가 반환되어야 한다.
- **FR-015**: 사용자는 로컬 파일을 케이스에 첨부할 수 있어야 한다.

**안전장치 (Safety)**

- **FR-016**: 외부에 실제로 전달되는 모든 동작(케이스 생성, 코멘트 추가, 속성 변경, 종료, 에스컬레이션, 첨부 업로드)은 실행 전에 전송될 내용을 사용자에게 제시하고 명시적 확인을 받은 뒤에만 실행되어야 한다.
- **FR-017**: 사용자가 확인 단계에서 취소하면 어떤 변경도 발생하지 않아야 한다.
- **FR-018**: 시스템은 쓰기 동작 전체 및 에스컬레이션을 개별적으로 비활성화할 수 있는 설정을 제공해야 한다. 기본 설정에서 에스컬레이션은 비활성 상태이며, 나머지 쓰기 동작(케이스 생성, 코멘트 추가, 속성 변경, 종료, 첨부 업로드)은 FR-016의 확인 절차를 거치는 조건으로 활성 상태여야 한다.
- **FR-019**: 비활성화된 기능이 요청되면, 시스템은 아무 변경도 하지 않고 해당 기능이 꺼져 있다는 사실과 활성화 방법을 안내해야 한다.

**인증·오류 처리 (Access & Errors)**

- **FR-020**: 시스템은 사용자 환경에 이미 구성된 Google Cloud 자격 증명을 사용해 인증해야 하며, 자격 증명을 별도로 저장하지 않아야 한다.
- **FR-021**: 시스템은 권한 부족, 지원 플랜 미가입, 자격 증명 없음/만료, 대상 없음, 요청 한도 초과를 서로 구분해 각각 다음 조치를 안내하는 문장으로 반환해야 한다. 위 어느 유형에도 해당하지 않는 실패에 대해서도, 사용자가 다음에 무엇을 시도해야 하는지 알 수 있는 기본 안내를 반환해야 한다.
- **FR-022**: 시스템은 케이스 본문, 코멘트, 첨부 파일 내용 등 지원 데이터를 로그나 진단 출력에 그대로 기록하지 않아야 한다.
- **FR-023**: 시스템은 반환하는 각 케이스에 대해, 사용자가 웹 콘솔에서 직접 열어볼 수 있는 참조 정보를 함께 제공해야 한다.

### Key Entities

- **Support Case (지원 케이스)**: 고객이 Google 지원팀에 제기한 하나의 문의 또는 장애 신고. 고유 식별자, 소속 프로젝트/조직, 제목, 설명, 문제 분류, 상태(열림/닫힘), 우선순위, 에스컬레이션 여부, 생성·갱신 시각을 가진다. 코멘트와 첨부 파일을 자식으로 가진다.
- **Case Comment (케이스 코멘트)**: 케이스 안에서 고객과 지원팀이 주고받는 하나의 메시지. 본문, 작성자(고객 측/지원팀 측 구분), 작성 시각을 가진다.
- **Case Attachment (첨부 파일)**: 케이스에 첨부된 파일. 파일명, 크기, 등록자, 등록 시각을 가지며 실제 내용은 별도 다운로드로 얻는다.
- **Case Classification (문제 분류)**: 케이스 생성 시 반드시 지정해야 하는 제품·문제 유형 분류. 표시 이름과 분류 식별자를 가지며, 유효한 값의 목록은 Google이 정의한다.
- **Parent Scope (조회 범위)**: 케이스가 속한 프로젝트 또는 조직. 모든 목록 조회와 케이스 생성의 기준이 된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 엔지니어가 대화를 벗어나지 않고, 담당 프로젝트에 열려 있는 모든 지원 케이스의 현재 상태와 최신 대화 내용을 한 번의 요청으로 파악할 수 있다.
- **SC-002**: 장애 정황을 이미 정리해 둔 상태에서, 새 지원 케이스 제출까지 3분 이내에 완료할 수 있다.
- **SC-003**: 도입 후 4주 시점에, 지원 케이스 확인·응답을 목적으로 한 웹 콘솔 방문 횟수가 **도입 직전 4주의 같은 목적 방문 횟수 대비** 80% 이상 줄어든다. (기준선은 도입 전에 측정해 두어야 한다.)
- **SC-004**: 케이스에 실제 변경을 일으키는 동작 중 사용자 확인 없이 실행되는 경우가 0건이다.
- **SC-005**: 의도하지 않은 케이스 생성·종료·에스컬레이션이 0건이다.
- **SC-006**: 시스템이 구분하는 모든 실패 유형에 대해, 그리고 어느 유형에도 해당하지 않는 실패에 대해서도, 사용자가 추가 조사 없이 다음에 무엇을 해야 하는지 알 수 있는 안내가 빠짐없이 제공된다.
- **SC-007**: 지원 케이스 API가 제공하는 케이스·코멘트·첨부·분류 관련 동작 중 90% 이상을 대화로 수행할 수 있다.
- **SC-008**: 처음 접하는 사용자가 별도 문서를 읽지 않고, 자격 증명 설정부터 첫 케이스 조회까지 10분 이내에 도달할 수 있다.

## Assumptions

- 대상 사용자는 Google Cloud 프로젝트를 운영하는 엔지니어·지원 담당자이며, 자신의 워크스테이션에서 MCP 서버를 실행한다. 다중 사용자용 공용 서버 운영은 v1 범위 밖이다.
- 인증은 사용자 환경에 이미 구성된 Google Cloud 자격 증명(Application Default Credentials 또는 서비스 계정)을 그대로 사용한다. 서버가 별도의 로그인 화면이나 자격 증명 저장소를 갖지 않는다.
- 대상 프로젝트/조직은 지원 케이스 API를 사용할 수 있는 유료 지원 플랜에 가입되어 있어야 한다. 미가입 환경에서는 조회조차 불가능하며, 이는 안내 대상 오류로 취급한다.
- 조회 범위는 프로젝트(`projects/*`)와 조직(`organizations/*`)을 모두 지원한다.
- Google Cloud Support API의 안정 버전(v2)을 기준으로 한다. 베타 전용 기능은 v1 범위 밖이다.
- **지원 이벤트 구독(Support Event Subscriptions)은 범위 밖이다.** 케이스 변경 사항을 서버가 먼저 알려주는 푸시 수신뿐 아니라, **구독 리소스의 생성·조회·수정·삭제·복구·영구삭제(CRUD)도 포함해 `SupportEventSubscriptionService` 전체를 제외한다.** 즉 이 서비스의 어떤 동작도 노출하지 않는다.
- 케이스 데이터를 별도로 저장하거나 캐시하지 않는다. 모든 조회는 Google 측 현재 상태를 반영한다.
- 사용자가 대화하는 어시스턴트가 MCP 서버를 호출하며, 사용자 확인 절차는 그 어시스턴트를 통해 사용자에게 노출된다.
- 인터페이스와 오류 메시지는 영어를 기본으로 하되, 케이스 본문·코멘트 등 사용자 데이터는 원문 그대로 전달한다.

## Dependencies

- Google Cloud Support API (v2) 및 해당 API가 활성화된 대상 프로젝트.
- 대상 프로젝트/조직의 유료 Google Cloud 지원 플랜.
- 지원 케이스 조회 및 편집에 필요한 IAM 권한이 부여된 사용자 또는 서비스 계정 자격 증명.
- MCP를 지원하는 클라이언트(어시스턴트).
